# QLinux カーネル基本設計 (モノリシック)

## 1. 方針

従来の QLinux は `key_pool` / `otp_engine` / `qhal` が std 依存のユーザランドライブラリで、
鍵材料がユーザ空間を通過していた。本設計ではこれらの役割をカーネル内に移し、
**単一カーネルイメージ・単一アドレス空間のモノリシックカーネル** とする。

* サブシステム間は IPC ではなく関数呼び出しで直接連携する
* 鍵材料はカーネル空間から出ない。ユーザ空間は syscall 経由で平文だけを扱う
* 鍵が尽きたら通信を止める。古典暗号 (AES/ECDHE 等) へのフォールバックはしない

```
 ┌──────────────── user space ────────────────┐
 │  app  ── SYS_QTLS_* / SYS_QKEY_AVAIL ──┐    │
 └────────────────────────────────────────┼────┘
 ┌──────────────── kernel (ring 0) ───────▼────────────────────────────┐
 │ syscall ─▶ net::KERNEL_NET (SpinLock<NetStack>)                     │
 │             L4+ QTLS   OTP XOR + ワンタイム Poly1305  ◀── qkey       │
 │             L4  UDP                                    鍵レーン      │
 │             L3  IPv4                                     ▲          │
 │             L2  Ethernet / ARP                           │          │
 │             L1  NIC (古典)        qphy (量子) ───────────┘          │
 │ scheduler / memory / ipc / drivers_core / ksync                     │
 └─────────────────────────────────────────────────────────────────────┘
```

## 2. クレート構成 (`kernel/`)

| クレート | 役割 |
|---|---|
| `qlinux-kernel` (`kernel/src`) | `kernel_main`、初期化順序、L1→鍵レーンのポンプ (`qkd_tick`)、パニック時の鍵消去 |
| `qphy` | **L1 量子物理層**。エンタングルメント / 高密度符号 / テレポーテーションによる鍵供給、QBER 検査、誤り訂正、3 量子ビットのステートベクタシミュレータ |
| `qkey` | カーネル内の使い捨て鍵ストア。ピアごとに送信・受信の 2 レーン |
| `net` | L2 Ethernet/ARP、L3 IPv4、L4 UDP、QTLS、カーネル唯一のスタック `KERNEL_NET` |
| `ksync` | スピンロック |
| `syscall` | 既存 syscall + QTLS 系 syscall (12–18) |
| `scheduler` / `memory` / `ipc` / `drivers_core` | 既存 |

## 3. L1: 鍵供給 (`qphy`)

物理層は両端ノードに **同一の鍵ブロック (256 B)** を供給する。モードは 3 つ。

| モード | 手順 | 1 ラウンドの鍵 |
|---|---|---|
| エンタングルメント (BBM92) | |Φ+⟩ を生成し B 側半分を伝送 → 両端が無作為基底 (Z/X) で測定 → 基底一致分を採用 | 1 bit (約 50% 採用) |
| 高密度符号 | 共有 |Φ+⟩ の A 側に I/X/Z/XZ で 2 bit を符号化して伝送 → B がベル測定で復号 | 2 bit |
| テレポーテーション | A が無作為基底で鍵量子ビットを用意 → 共有ベル対でテレポート (補正 2 bit は L2/IP の認証付き古典チャネル) → B が無作為基底で測定 | 1 bit (約 50% 採用) |

蒸留手順 (`SimQuantumLink::harvest`)。出力の 2 倍 (RAW) の生鍵を集めてから増幅する:

1. **[FIX-1] 検査ラウンド**: 各ラウンドで 1/4 の確率で、鍵ラウンドの代わりに BBM92 相関テスト
   (もつれ対を無作為基底で両端測定) を秘密裏に挟む。鍵ラウンドと伝送上区別できないため、
   盗聴 (intercept-resend) も**ベル対すり替えの中間者**も検査ラウンドを乱して露見する。
   高密度符号モードでは鍵ビット自体 (a==b) が中間者を検出できないので、この検査が要
2. **QBER > 11% なら盗聴ありとしてブロック破棄** (`PhyError::QberExceeded`)
3. Cascade 風の反復 BINARY 法で誤り訂正 (最大 12 スーパーラウンド×5 パス、ラウンドごとに
   区間長・置換を変える)。公開パリティ数を `leaked_bits` に記録
   * 置換により、高密度符号で 1 回のパウリ誤りが隣接 2 bit を反転させるケースも訂正できる
   * 反復により QBER 10% 近くまで訂正可能 (以前の単発版は 2% 程度で破綻していた)
4. 一致しない場合は破棄 (`ReconciliationFailed`)
5. **[FIX-2] プライバシー増幅**: Toeplitz ハッシュで RAW → 出力長に圧縮する。
   盗聴者が持ちうる情報 `h2(QBER)·RAW` と誤り訂正の公開パリティ `leaked_bits` に
   安全マージンを加えて差し引き、残り安全ビットが出力長に満たなければ破棄
   (`PhyError::InsufficientSecrecy`)。行列は公開シードから両端で決定的に生成する
   * シミュレーション: 雑音 ~4% まで鍵生成、~5–11% は増幅で破棄、>11% は QBER で破棄

ブロック番号 `seq` の偶奇で鍵レーンを割り当てる (偶数 = A→B、奇数 = B→A)。
両端が同じ `seq` を同じレーンに積むため、双方向で同じ鍵を使うことはない。

実機ドライバは `QuantumLinkDriver` トレイトで差し替える。QEDA チップ用の
`QedaChipDriver` は現時点で `NoDevice` を返し、その場合 QTLS は鍵不足で無効になる。

## 4. 鍵ストア (`qkey`)

* 鍵バイトは **絶対オフセット (u64)** で識別。両端で同じオフセット = 同じ鍵バイト
* 送信: `take` で先頭から取り出し、その場でゼロ化
* 受信: `peek_at` でタグ検証 → 成功時のみ `consume_through` で消費・ゼロ化
  * 消費済みオフセットは `AlreadyConsumed` (リプレイ/再利用拒否)
* **[FIX-4] スライディングウィンドウ**: レーン (16 KiB/方向) が満杯のとき、`deposit` は
  最古の未使用鍵を捨てて新しい鍵を受け入れる。両端が同じ絶対オフセットに同じバイトを
  持つ性質は保たれるため、パケット欠落で片側だけ消費が進んでも窓が相手を追い越さず、
  妨害が止めば自動的に再同期する (以前は片側 `LaneFull` で恒久非同期していた)
  * 読み飛ばし上限 (旧 `MAX_RX_SKIP`) は撤廃。偽オフセットのレコードはワンタイム
    Poly1305 タグ検証で必ず弾かれ、検証前に鍵は一切消費されないため DoS にならない

## 5. L2–L4: IP スタック (`net`)

L2/L3 は通常の IP ネットワークをそのまま使う。

* Ethernet II、ARP (要求/応答、8 エントリのキャッシュ)
* IPv4: ヘッダチェックサム検証、フラグメント非対応 (DF 付き送信、断片は破棄)
* UDP: 疑似ヘッダ付きチェックサム

## 6. L4: QTLS (SSL/TLS からの分岐)

TLS のレコード層の位置に置くが、ハンドシェイクの鍵交換と共通鍵暗号を廃し、
**OTP (XOR) + 使い捨て鍵** に置き換える。UDP 上で動作 (既定ポート 4433)。

```
 0      1        2           4             12       14            14+len
 | type | version | session_id | key_offset   | length | ciphertext | tag(16) |

 key[off      .. off+32    ]  → Poly1305 ワンタイム鍵 (Wegman-Carter 認証)
 key[off+32   .. off+32+len]  → XOR パッド (OTP)
```

* 1 レコードの鍵消費量 = 32 + 平文長
* OTP は可鍛性があるため、ワンタイム鍵の Poly1305 で header ∥ ciphertext を認証 (情報理論的安全)
* `Hello` / `HelloAck`: 空ペイロードのレコード。双方が同じ鍵ストリームを持つことの相互確認
* 鍵を共有していない (量子リンクの無い) ホストからのパケットは全て破棄
* 受信は鍵オフセット順。遅延して届いた古いレコードは `AlreadyConsumed` で破棄

## 8. セキュリティ修正の記録

脆弱性チェックで見つかった問題への対応。各修正には回帰テスト
(`*/tests/poc_attacks.rs`、`fixN_*`) を付けている。

| # | 深刻度 | 問題 | 修正 |
|---|---|---|---|
| FIX-1 | 高 | 高密度符号モードがベル対すり替え中間者を検出不能 | 鍵ラウンドと区別できない BBM92 検査ラウンドを 1/4 挿入し QBER に反映 |
| FIX-2 | 高 | プライバシー増幅が無く、部分盗聴・EC 公開で鍵が漏れる | Toeplitz ハッシュで RAW→出力に圧縮し、`h2(QBER)·RAW + leaked_bits + 余裕` を控除。不足は `InsufficientSecrecy` で破棄 |
| FIX-3 | 高 | `validate_user_ptr` がカーネル静的領域 (鍵) を通す | `set_kernel_image` でイメージ範囲を登録し重なるポインタを拒否 (暫定。本来はページング + SMAP/SMEP) |
| FIX-4 | 中 | パケット欠落で鍵レーンが恒久非同期 | `deposit` をスライディングウィンドウ化し読み飛ばし上限を撤廃。妨害停止後に自動再同期 |
| FIX-5 | 中 | ロック保持中のパニックで鍵が消えない | `emergency_zeroize` がロック取得失敗時に強制消去へフォールバック |
| FIX-OVF | 高 | 攻撃者制御の `key_offset` による整数オーバーフロー (タグ検証前の `peek_at`)。debug ビルドでは遠隔 panic、release ではバウンドチェックすり抜け | `qkey` の `peek_at`/`consume_through` を checked u64 演算に変更。`tests/poc_attacks.rs` にオーバーフロー回帰テストとパーサ・ファズ (2 万件) を追加 |
| 低 | 低 | ARP キャッシュ汚染 | 登録済み量子ピアの IP のみ ARP 学習 |

メモリ安全性の確認: debug ビルド (算術オーバーフローチェック ON) で全テストとパーサ・ファズが
パニックなく通ることを確認済み。L2–L4 のパース・チェックサム・コピーは入力長で上限が付き、
Toeplitz・誤り訂正の添字・鍵レーンのリング演算は範囲内に収まることを確認した。

### 意図的なフェイルクローズ (脆弱性ではない)
* ハードウェア乱数 (`RdRand`) 枯渇時は panic → halt。弱い鍵を使うより停止を選ぶ

## 9. 未実装・既知の制約

* FIX-3 は暫定措置。アドレス範囲チェックのみで、本来はページテーブルによる特権分離 + SMAP/SMEP が必要
* L1 の基底照合・誤り訂正の古典通信は、シミュレータ内では直接比較で模擬している。実機では事前共有鍵で認証した L2/IP チャネルが必要
* QTLS はレコードを順序どおり受け取る前提。大きな並べ替えが起きると FIX-4 の追従で古いレコードが `AlreadyConsumed` になる (再送機構なし)
* UDP ヘッダ (ポート) は QTLS の認証対象外。平文長も OTP の性質上秘匿されない
* テレポーテーションの中継 (3 ノード以上のリピータ) は対象外。現状は 2 ノード直結のみ
* NIC は Loopback のみ (virtio-net / e1000 ドライバ未実装)。割り込み駆動ではなく `poll` 駆動
* TCP 非対応。QTLS は UDP 上のみ
* `SpinLock` は割り込みを禁止しない。割り込みハンドラからスタックを触る場合は要対応
* レーン容量 16 KiB/方向、ピア 2、セッション 4 (いずれも静的確保)
